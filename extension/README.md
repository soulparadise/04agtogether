# 04agtogether · Chrome Extension 0.2.2 · этап 7

Chrome 119+, Manifest V3. Один профиль Chrome = один участник/плеер. Локальная проверка с адресом 127.0.0.1 выполняется в двух профилях на одном компьютере. Расширение пока подключается к локальному приложению, не к действующему soulparadise.ru.

[Исследование первого киносайта и короткая проверка двумя участниками](SITE-SUPPORT.md). На Lordfilm фактически воспроизводилось HTML5-видео в src-less iframe; версия 0.2.1 добавила обнаружение таких разрешённых фреймов. Пользователь подтвердил работу первого Full HD-плеера; работа второго с расширением ещё требует подтверждения.

Версия 0.2.2 учитывает переключение вкладок плееров: скрытый старый iframe исключается, активный выбирается заново. **«Плеер 2»** использует отдельный origin **https://cdn.lordfilm64.com**: если Chrome ещё не получил разрешение, в popup появится **«Разрешить плеер: cdn.lordfilm64.com»**. Это нужно сделать у обоих участников, выбрав одинаковый плеер и озвучку. После выдачи разрешения повторная привязка выполняется автоматически.

## Установка

Из корня проекта:

```powershell
pnpm build:extension
pnpm dev
```

Открыть `chrome://extensions`, включить «Режим разработчика», нажать «Загрузить распакованное расширение» и выбрать `D:\AI Projects\o4agtogether\extension\dist`. Закрепить 04agtogether через меню расширений. После изменения исходников повторить сборку, нажать «Обновить» на карточке расширения и обновить тестовые вкладки.

ID `igpjafcbhhcandncnhdfpphkidmcpigh` стабилен благодаря публичному `identity.json` (это не приватный ключ). Только этот Origin разрешён отдельным локальным dev-backend. Production по умолчанию не разрешает Origin расширений.

## Совместный просмотр

1. Владелец открывает страницу фильма, нажимает расширение → **«Смотреть вместе»**. В первый раз указывает никнейм и разрешает доступ к сайту и локальному приложению. Дальше никнейм не спрашивается. Комната создаётся автоматически, текущая позиция сохраняется, плеер подключается сразу.
2. Владелец нажимает **«Копировать приглашение»** и отправляет обычную ссылку комнаты. Секретов в ней нет.
3. Зритель открывает приглашение в другом профиле Chrome/на другом компьютере. Никнейм нужен только в первый раз; сохранённый используется автоматически. В комнате видны фильм, участники и кнопка **«Открыть фильм»**.
4. По этой кнопке расширение само открывает страницу и подключает плеер. Если доступ к новому сайту ещё не выдан, появляется компактное окно расширения: **«Открыть фильм»** вызывает штатный запрос разрешения Chrome и продолжает открытие. Этот шаг нужен только из-за требования браузера запрашивать разрешения внутри пользовательского жеста. При уже выданном доступе дополнительного окна нет.
5. При запрете autoplay нажать **«Начать просмотр»** на странице. Play/Pause/Seek владельца идут зрителю через прежний протокол. Для недоступного cross-origin iframe расширение предлагает разрешить именно его адрес; DRM/закрытые плееры не обходятся.
6. Обновление фильма и перезапуск service worker восстанавливают выбранную вкладку. Закрытие вкладки, уход на другой фильм или **«Отключиться»** освобождают управление и сеанс. Другие вкладки, даже с таким же фильмом, автоматически не подключаются. Новый фильм → новое нажатие «Смотреть вместе» и новое приглашение.

Токены изолированы в `chrome.storage.session` (доступ только доверенным контекстам расширения) и сетевом worker. В URL, DOM сторонней страницы, content script или журналы они не передаются. Веб-приложение передаёт свою существующую сессию через `runtime.sendMessage`; backend проверяет её через прежний `room:resume`. Никнейм хранится отдельно как обычная настройка. После полного завершения Chrome секретное хранилище расширения очищается; после перезапуска backend комнаты удаляются.

Мост принимает сообщения только от верхнего фрейма точных origin `http://127.0.0.1:5173`, `http://localhost:5173` (и локальных production-портов 3000) либо `https://soulparadise.ru`. Для операций комнаты проверяется её путь; origin берётся из Chrome sender, а не из тела сообщения. Произвольные LAN-IP для этого моста не разрешены. Обычный LAN/Embedded режим сохраняется.

## Стандартная тестовая страница

```powershell
pnpm test:video          # только если ещё нет MP4; нужен ffmpeg
pnpm dev:extension-site  # отдельный терминал, 127.0.0.1:5174
```

Открыть **http://127.0.0.1:5174/** и нажать в расширении **«Смотреть вместе»**. Это другой origin с обычным HTML5 video; MP4 загружается непосредственно оттуда. Кнопка «Сменить видеоэлемент» проверяет повторное обнаружение. Тестовая страница слушает только loopback и не нужна для других сайтов.

## Архитектура и ограничения

`content.mjs` работает в ISOLATED world, выбирает крупнейшее video доступного фрейма, следит за заменой через MutationObserver. `ForeignVideoAdapter` сохраняет URL/загрузку сайта и использует существующий `PlaybackSync`. Ожидаемые программные события подавляются, Viewer не отправляет управляющие команды.

Service worker занимается разрешениями и маршрутизацией. Offscreen-документ с причиной WORKERS создаёт настоящий dedicated worker, владеющий Socket.IO HTTP polling; закрытие popup и обычное засыпание service worker не прерывают соединение. Всё исполняется из локальной сборки, без удалённого JS/eval. Права владельца проверяются backend при каждой команде.

Локальная сборка использует `http://127.0.0.1:5173`. Будущий production-адрес уже учтён в проверках моста; для отдельного согласованного развёртывания сборка допускает `EXTENSION_APP_ORIGIN=https://soulparadise.ru`, а backend — явный `EXTENSION_ORIGINS=chrome-extension://igpjafcbhhcandncnhdfpphkidmcpigh`. По умолчанию production по-прежнему запрещает Origin расширений. В этом этапе production не запускался на хостинге и его настройки не менялись.

Нет обхода DRM, авторизации, anti-bot, sandbox или политики autoplay. Закрытые Shadow DOM, недоступные iframe, нестандартные SDK-плееры, несколько одновременно активных роликов, реклама вместо основного видео и разные монтажи фильма требуют дополнительной поддержки. Пока не реализованы аккаунты и восстановление комнаты после полного перезапуска Chrome/backend.

Проверка этапа 6: 36/36 автоматических тестов, production build и сборка расширения 0.2 прошли. Новые проверки охватывают доверенный источник передачи сеанса, создание комнаты, роли и восстановление привязки. Переход зрителя, разрешения, повторная загрузка обработчика и закрытие вкладки проверены в Chrome API harness; это не фактический прогон расширения в Chrome. В браузере отдельно подтверждены воспроизведение Embedded и автоматический вход по приглашению с сохранённым никнеймом. Полный новый сценарий в установленном Chrome ещё требует фактической проверки.
