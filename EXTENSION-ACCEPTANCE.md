# Проверка основного сценария расширения · 0.2.9

Дата: 31 октября 2026, Europe/Moscow.

Работа и отчёты ведутся по согласованному [PROJECT-CONTRACT.md](PROJECT-CONTRACT.md). Этот документ описывает проверку; наличие инструкции не означает прохождение сценариев.

Уточнение владельца: тест проводится в **двух браузерах на одном ПК** — **A: Яндекс Браузер / Owner**, **B: Google Chrome / Viewer**. Расширение устанавливает и обновляет только владелец вручную. При каждой необходимости установки/обновления агент сообщает версию и папку, затем ждёт явного подтверждения выполнения; без него проверка, зависящая от новой установки, не начинается. Совместимость 0.2.9 с Яндекс Браузером входит в этот тест и пока не подтверждена.

## 4. Только автоматические тесты или модели

Ранее пройдено 48/48 тестов, build и loopback smoke; в этом продолжении они не повторялись, так как код не менялся.

- Настоящий локальный HTTP polling: права ролей, Play/Pause/Seek, восстановление, продолжение созданной на сайте Owner-комнаты.
- Chrome API harness: соответствие комнаты и вкладки, переход после выдачи разрешения, перепривязка фрейма без подтверждения общего выбора.
- Скомпилированный content-контроллер с моделями DOM/video: независимая смена плеера, ленивый Allplay, отсутствие ложной общей Pause.
- Модели media element: лишний seek при canplay (до исправления тест падал), буферизация и незавершённая перемотка.
- Модель permissions API: повторное использование выданного доступа, запрос только недостающего адреса, учёт отзыва.

Эти результаты не являются тестом установленного расширения на реальном сайте. Ранее проверенные два настоящих HTMLVideoElement с прямым MP4 относятся к вспомогательному Embedded-сценарию.

## 5. Ограничения и известные проблемы

- Инвентарь Windows показал одно окно Яндекс Браузера с текущим полноэкранным просмотром. Два независимых профиля Chrome с установленной 0.2.9 не обнаружены и не подготовлены. Версия расширения в пользовательском браузере не проверена. Это не утверждение, что Chrome невозможно установить или что его нет на диске.
- Подключённый браузерный инструмент предоставляет IAB без установленного расширения. Две IAB-вкладки не создают два экземпляра расширения. Подмена Chrome API и внедрение собранного скрипта на сайт не используются как замена установке.
- Установка расширения, создание/переключение пользовательских профилей и выдача новых разрешений не выполнялись. Защитные ограничения сайта и браузера не обходились.
- Точная причина сегодняшних «слайдов» не установлена. Исправлен воспроизведённый дефект коррекции времени; остаются возможными проблемы конкретного потока, качества, сети, декодирования или разных монтажей. Нужен сравнительный тест с расширением и без него.
- Новые домены iframe могут требовать штатного доступа, autoplay — отдельного клика. Это разные действия. Новая 0.2.9 ещё не проверена в Яндекс Браузере.

Нужны **Яндекс Браузер (Owner) и Google Chrome (Viewer) на одном ПК**, каждый с установленной локальной development-сборкой 0.2.9. Дополнительные профили Chrome не требуются. ### Подготовка

Используются два разных браузера с отдельным хранилищем расширения. Если в них уже есть стабильная 0.2.6, владелец сам выбирает и выполняет штатное обновление на локальную сборку для теста. Агент не переустанавливает расширение и не меняет его разрешения самостоятельно.

1. В папке `D:\AI Projects\o4agtogether` запустить `pnpm dev`. Дождаться адреса `http://127.0.0.1:5173`. После проверки остановить Ctrl+C. При совместной проверке агент сообщает отдельно, запущен ли сервер сейчас.
2. Владелец вручную устанавливает/обновляет расширение в **Яндекс Браузере и Google Chrome** из папки `D:\AI Projects\o4agtogether\extension\dist`, затем проверяет версию **0.2.9** и ID. В обоих браузерах используется одна и та же папка. Для Chrome распакованная загрузка описана в [официальной инструкции](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked). Если Яндекс Браузер не принимает эту сборку штатным способом, передать точное сообщение; не обходить запрет и не считать совместимость подтверждённой.
3. Сообщить агенту, что установка завершена в обоих браузерах. Только затем обновить вкладки фильма/локального сайта и проверить обнаружение расширения. **A — Яндекс / «Владелец теста»; B — Chrome / «Зритель теста».** Использовать локальную страницу, не soulparadise.ru и не публичный ZIP.

Для первого запуска локального сервера достаточно открыть терминал в папке проекта и выполнить `pnpm dev`. До запуска профилей проверить, что в терминале появился адрес `http://127.0.0.1:5173`, а не ошибка занятого порта. Ничего не завершать и не перенастраивать ради освобождения порта без выяснения причины.

В локальном режиме кнопка скачивания ZIP на сайте может быть недоступна: расширение уже берётся из подготовленной папки, скачивать публичный ZIP не нужно. После загрузки расширения обновить вкладку локального сайта, при необходимости нажать «Проверить расширение». Если оно не обнаружено, остановиться на этом шаге и передать фактическое сообщение; не считать открытие обычного video проверкой расширения.

Первый контрольный рубеж: оба браузера показывают 0.2.9, локальный сайт видит расширение, Owner в Яндексе открыл фильм из комнаты, Viewer в Chrome вошёл по приглашению и открыл тот же фильм. Только после этого переходить к проверкам Play/Pause и остальных пунктов матрицы.

Минимальная запись результата: версия/профиль A и B; номер сценария; «прошёл/не прошёл»; фактическое поведение; тексты двух popup; позиции на общей паузе; новый домен при запросе разрешения. При рывках полезна короткая запись экрана, если пользователь готов её предоставить.

### Форма фактического результата

Заполняется после действий в реальном браузере; пустые поля означают, что проверки ещё нет.

| Поле | Факт |
|---|---|
| Дата и время теста | Не заполнено |
| Браузер и версия у A / B | Не заполнено |
| Версия расширения у A / B | Не заполнено |
| Адрес приложения | Ожидается http://127.0.0.1:5173; фактически не заполнено |
| Фильм: полный адрес страницы | Не заполнено |
| A: плеер / перевод / качество | Не заполнено |
| B: плеер / перевод / качество | Не заполнено |
| Номер сценария | Не заполнено |
| Действие A и фактическая реакция B | Не заполнено |
| Текст popup A / B после действия | Не заполнено |
| Позиции A / B на общей паузе | Не заполнено |
| Запрос: домен / autoplay / другое; при первом или повторном переходе | Не заполнено |
| Рывки: без подключения / с подключением, участок и длительность | Не заполнено |
| Итог: прошёл / не прошёл / не выполнен | Не выполнен |

Если браузеры готовы, но не подключены к инструментам агента, владелец выполняет действия по матрице и передаёт заполненные факты. Сообщение «установлено в обоих» подтверждает только установку, а не прохождение приёмки.

Для двух физических устройств этот loopback-план не подходит: у каждого свой 127.0.0.1, а текущий мост расширения не разрешает произвольный LAN-origin. Не подменять адрес сервера самостоятельно и не использовать production для обхода этого ограничения. Такая конфигурация потребует отдельного согласованного плана.
